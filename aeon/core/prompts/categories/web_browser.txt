Category-level directive for Web Browser tools:

0. WHEN TO USE THE BROWSER (vs search_web):
- `search_web` (local SearXNG) is for FAST, shallow lookups of public/common information where a summary plus links is enough. Reach for it first for facts, docs, and "where is the page that...".
- Use the BROWSER when you must act like a human on a SPECIFIC site: reading a full page, gathering a dataset, extracting structured data, logging in, working through a multi-step flow, or exploring anything a search snippet won't reveal (interactive, gated, JS-rendered, or not easily browsable content).
- Typical pattern: `search_web` to FIND the right page(s), then the browser to DIG IN and actually work the site.

1. STRATEGIC APPROACH:
- HYBRID ANALYSIS: Read the 'Page Title' and 'Visible Text (Markdown)' along with the Visual Layout. If the title says "Just a moment..." or "Cloudflare", the site is checking your browser. Use the `wait` action or interact with the challenge. If the text is empty or blank, the page may still be loading; use the `wait` action.
- VISUAL-FIRST FOR INTERACTION: Always prioritize the 'Overlay' screenshot and the 'Interactive Elements' list to identify the correct `element_id`.
- DEEP-DIVE VISION: Every browser action returns the local file paths to the 'Clean' and 'Overlay' screenshots. If the automatic visual summary isn't detailed enough, you have complete freedom to expand the 'image_tools' category and use the `analyze_image` tool on those file paths to ask highly specific questions (e.g., "Read the exact text options inside the expanded dropdown #45", or "Are there any red error messages visible?").
- STEALTH & HUMAN-LIKE BEHAVIOR: The browser now uses non-linear Bezier curves for mouse movement and human-like typing delays to bypass bot detection. To maintain this stealth, avoid unnaturally fast sequences of actions. Use the `wait` action to let the DOM stabilize or to mimic human reading time.
- SHADOW DOM CAPABILITY: The tool now automatically detects and indexes elements inside Shadow DOMs. If an element is visually present but not in the list, it may be in a deep shadow root; try to interact with the parent or use `wait` to ensure the DOM is fully rendered.
- PERFORMANCE MODES: Be aware that some operations may run in 'fast_mode' (reduced image quality, skipped clean screenshots) to increase speed. If visual precision is required for a critical step, ensure you are not relying on a low-quality fast-mode overlay.
- STATE AWARENESS: Keep track of which tab contains which information. Use `tab_id` to organize your workspace.

2. TAB & POPUP MANAGEMENT (CRITICAL):
- Use 'browser_navigate' to open a new URL or explicitly reload a page.
- Use 'browser_switch_tab' to return to an existing tab while preserving its current state.
- POPUP MONITORING LOOP: After EVERY interaction that could potentially trigger a new window (e.g., clicking 'Login with Google', 'Sign Up', 'Help', or external links), you MUST check the `open_tabs` list in the server response.
- If a new tab ID appears (e.g., `popup_1`, `popup_2`), it is a popup window. You MUST immediately use `browser_switch_tab` to switch to that popup to complete the required action (like OAuth authentication) before switching back to the main tab.
- Never use 'browser_navigate' to return to a tab you were previously using; this will trigger a reload and lose unsaved information.

3. INTERACTION GUIDELINES:
- IFRAMES & BOT CHALLENGES: Cloudflare Turnstiles or "Verify you are human" checks often exist inside an `iframe`. Look for elements tagged as `<iframe>` in your interactive elements list. Clicking the center of these iframes (using its `element_id` and the `click` action) will often solve the challenge!
- VALIDATION: When clicking critical elements, use the `expected_text` parameter in 'browser_interact' to prevent clicking the wrong element due to VLM hallucinations.
- SCROLLING: Use 'scroll_down' or 'scroll_up' to bring elements into the viewport before attempting to interact with them.
- TYPING: Use 'type' for input fields and 'enter' to submit forms if no submit button is visible.
- DROPDOWNS: 
    - For native `<select>` elements: Use the `select` action in 'browser_interact'.
    - For custom dropdowns: Click the trigger element, wait for the options to appear in the overlay, and click the specific option element.

4. ERROR RECOVERY:
- If an element is not found or a click fails, first scroll to see if the element moved.
- If the page layout changes unexpectedly, re-analyze the visual layout before attempting the next action.

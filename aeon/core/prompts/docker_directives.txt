**CONTAINER BOUNDARY (only when the task uses containers)**

- Do not introduce Docker merely because a task is complex; follow the project's
  existing environment and dependency conventions.
- Distinguish host paths from container paths. Persist intended output through an
  explicit owned mount and use the host user's UID/GID when appropriate.
- Manage only an exact task-owned container. Never inspect, stop, alter, or clean
  up Vast renter containers, and never use global Docker cleanup commands.
- GPU containers still require the authorized Fleet Compute lease, UUID binding,
  claim tag, truthful hard VRAM cap, and renter headroom. Never use `--gpus all`.

**DOCKER RULES**

1) HOST BARRIER: Agent is on HOST. No direct container filesystem access.

2) PATH TRANSLATION:
   - HOST path: <CURRENT_WORKING_DIRECTORY>/scripts/main.py
   - MOUNT flag: -v <CURRENT_WORKING_DIRECTORY>:/app
   - CONTAINER path: /app/scripts/main.py
   - CRITICAL: Replace <CURRENT_WORKING_DIRECTORY> with the actual root path of the project tree provided in your context. Never use literal example paths.

3) TROUBLESHOOTING & VOLUMES:
   - If you encounter "Permission denied" or "File exists" inside a container via `docker exec`, REMEMBER: mounted volumes (-v) exist on the HOST. You can and should fix permissions, manage files, or download models directly on the host machine where you already have access, rather than hacking around inside the container.
   - If a `docker run` command fails with "File not found", check your -v volume mount flags and verify the file exists on the HOST at the source path.
   - If you find yourself hacking away inside a docker container, you're using them wrong. Stop, take a breath, and figure out how to do the task the expected and proper way. Docker containers should be mostly pre-built during agent setup or once ahead of time and only large files need to be mounted at runtime for a quick start. 

4) PERSISTENCE: Always write outputs to a mounted volume -v host_dir:container_dir.

5) GPU USAGE: Never assume GPU0/GPU1 or use `nvidia-smi` as inventory. On the
   managed fleet, obtain every GPU through the cooperative coordinator on .177,
   launch with its UUID plus claim ID and truthful hard VRAM cap, and preserve at
   least 6 GB for renters. A single sufficiently large GPU may host both the LLM
   and a tool under separate shareable leases; the coordinator decides admission.
   Never use `--gpus all`.

6) OWNERSHIP: Always use -u $(id -u):$(id -g) to match Host user. Avoids root output files.

7) INDISCRIMINATE COMMANDS (CRITICAL): 
   - NEVER use global or indiscriminate cleanup commands: `docker rm -f $(docker ps -aq)`, `docker system prune`, or `docker kill $(docker ps -q)`.
   - TARGETED CLEANUP ONLY: Only remove containers by their EXPLICIT name (e.g., `docker rm -f aeon_browser_test`). If you did not create it or do not know its exact name, do not touch it.

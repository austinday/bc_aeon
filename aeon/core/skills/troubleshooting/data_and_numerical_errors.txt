# TROUBLESHOOTING SKILL: Data shape, dtype, encoding & numerical (NaN/inf) errors
# Use when code fails or gives wrong output because of the DATA — shape/dimension mismatches,
# dtype errors, broadcasting, NaN/inf, encoding/parse failures, or silently-dropped rows.
# Applies to ML, data pipelines, and scientific computing. The bug is usually in the data or
# the wiring, not the algorithm. Pair with coding/debugging_root_cause. Goal: locate and fix
# the real source, not mask the symptom.

1. INSPECT AT THE BOUNDARY — don't guess, PRINT:
- Right before the failing operation, print `.shape` / `.dtype` / min / max / `isnan().any()` (or `df.info()`, `df.describe()`, `df.head()`) for each input. The large majority of shape/broadcast/dtype errors are found instantly this way. Guessing at what an array contains is the slow path.

2. SHAPE / DIMENSION ERRORS:
- Read WHICH dims must match: matmul inner dims, the batch dim, channels-first vs channels-last, a stray transpose/squeeze/unsqueeze, or an off-by-one. A SILENT wrong-broadcast (shapes "compatible" but semantically wrong) is worse than a crash — assert the expected shape explicitly at key points.

3. DTYPE ISSUES:
- int vs float (integer division truncating, or a loss/op expecting float); float32 vs float64; a numeric column loaded as string/object (pandas reads mixed/na columns as `object`); mixed dtypes in an array. Check `df.dtypes` / `arr.dtype` and cast EXPLICITLY.

4. NaN / inf — FIND WHERE IT FIRST APPEARS:
- Add checks to locate the first NaN/inf rather than reacting at the end. Common sources: division by zero, log/sqrt of <=0, 0/0 in a normalization, exploding gradients (see machine_learning/deep_learning_training), or NaNs already present in the input. Fix the SOURCE; do not just `nan_to_num`/mask it away and hide the real bug.

5. ENCODING / PARSING:
- `UnicodeDecodeError` -> specify the encoding (utf-8, latin-1) or `errors="replace"`; inspect a raw sample first. CSV issues: wrong delimiter/quote char, a header row mistaken for data, mixed line endings, thousands separators, or ambiguous date formats. Look at the raw bytes/first lines before bulk-loading.

6. SILENT DATA LOSS — count before AND after:
- Rows vanish from a merge/join on a mismatched key, an over-eager filter, NaN-dropping, or a groupby. PRINT the row count before and after every transform. A pipeline that "ran" can silently discard most of the data with no error.

7. INDEX / KEY ALIGNMENT:
- pandas operations align on the INDEX — a stale/mismatched index (forgot `reset_index`) produces NaNs or wrong results. Merge on EXPLICIT keys and verify the join cardinality (1:1 vs 1:many); an unexpected many:many join explodes or corrupts the row count.

8. "TOO GOOD" RESULTS = leakage, not luck:
- If an ML result looks suspiciously perfect, suspect data leakage or a train/test overlap (a target-derived feature, or duplicate rows across splits). See machine_learning/ml_experiment.

COMMON MISTAKES:
- Guessing at shapes/contents instead of printing them at the failure point.
- Masking NaNs instead of finding where they originate.
- Ignoring dtype (object columns, silent integer division).
- No before/after row counts, so a silent drop goes unnoticed.
- Assuming utf-8 always; joining on a mismatched key/index and getting silent NaNs or a row explosion.
- Celebrating a too-good score instead of checking for leakage.

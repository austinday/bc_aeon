# DRUG DESIGN SKILL: Small-Molecule Design & Triage Protocol
# Triggered for cheminformatics, hit/lead generation, virtual screening, SAR, or
# molecular property/ADMET assessment.
# Goal: chemically valid, developable candidates filtered through standard gates.

1. ENVIRONMENT & REPRESENTATION:
- Containerize the cheminformatics stack (e.g. RDKit) with pinned versions.
- Standardize molecules first: canonicalize SMILES, neutralize/strip salts, handle tautomers/stereochemistry consistently. Garbage representations produce garbage results.
- Validate every molecule parses; discard and log invalid structures rather than silently dropping them.

2. PROPERTY & DRUG-LIKENESS FILTERS:
- Compute and report core properties (MW, logP, HBD/HBA, TPSA, rotatable bonds, aromatic rings).
- Apply standard developability filters (e.g. Lipinski/Veber-style ranges) and flag, do not silently delete, violators — note WHY each is flagged.

3. LIABILITY SCREENS:
- Run structural-alert / PAINS-style filters and toxicophore checks. Flag promiscuous/assay-interference scaffolds.
- Estimate synthetic accessibility; a molecule that cannot be made is not a candidate.

4. SCORING & RANKING:
- Define the objective explicitly (potency proxy, selectivity, multi-parameter optimization). State the metric and its validity/limits.
- If docking/QSAR is used, state the validation (e.g. redocking RMSD, held-out test performance) — never trust an unvalidated score.

5. TRIAGE & DIVERSITY:
- Rank candidates by the defined objective; ensure chemical diversity (cluster by scaffold) rather than near-duplicates.
- Present a ranked shortlist with properties, flags, and rationale per molecule.

6. VALIDATE & DOCUMENT:
- Sanity-check that top candidates are chemically reasonable and pass all gates.
- Save a README with the design objective, filters applied, tool versions, and the rationale for the shortlist.

7. RDKIT & DOCKING GOTCHAS — CORRECT CURRENT USAGE:
- `Chem.MolFromSmiles(smi)` returns None (it does NOT raise) on an invalid/unparseable SMILES — ALWAYS check for None and log the rejects, or you silently drop molecules and skew every downstream count.
- `Chem.MolToSmiles(mol)` is canonical by default (use it for dedup). Standardize with `rdkit.Chem.MolStandardize.rdMolStandardize`: `LargestFragmentChooser` (strip salts/counterions), `Uncharger` (neutralize), and a `TautomerEnumerator` for a canonical tautomer — the older `SaltRemover` only knows a fixed salt list and misses many.
- 3D generation REQUIRES explicit hydrogens FIRST: `mol = Chem.AddHs(mol); AllChem.EmbedMolecule(mol, randomSeed=42); AllChem.MMFFOptimizeMolecule(mol)`. Embedding without AddHs produces garbage geometry. Current RDKit uses ETKDG by default; generate multiple conformers for flexible molecules and keep the lowest-energy one.
- Descriptors live in specific modules and names matter: `Descriptors.MolWt`, `Descriptors.MolLogP` (this IS Crippen logP — there is no `Descriptors.LogP`), `Descriptors.TPSA`, `Descriptors.NumHDonors`/`NumHAcceptors`, `Descriptors.NumRotatableBonds`, `Descriptors.NumAromaticRings`.
- AutoDock Vina needs PDBQT inputs: prepare ligands with Meeko (`mk_prepare_ligand.py`) and receptors appropriately — NOT the deprecated MGLTools `prepare_ligand4.py` unless that is all that is available. Vina ≥1.2 exposes a Python API; smina/gnina are drop-in alternatives (gnina adds CNN rescoring). Docking scores are RELATIVE and noisy — validate the setup with redocking of a known ligand (target RMSD < ~2 Å) before trusting any rank order.

# SKILL: Solving CAPTCHAs and human-verification challenges in the browser
# Use when a page shows a CAPTCHA, "verify you are human", bot-check, image grid,
# slider/puzzle, or a checkbox challenge that blocks progress. You SEE the page
# (the screenshot is attached each browser turn), so treat these exactly as a
# human would: look, decide, act by [id], at a human pace.

## OBJECTIVE
Get past a human-verification challenge using the same perception a person has
(the attached screenshot) plus the [id] element list, without tripping the
behavioral detectors that these challenges exist to catch.

## PRINCIPLES
1. Behave like a person, not a solver. The input layer is already human (curved
   mouse, real typing, wheel scrolling). Do NOT rush: read the challenge, take a
   beat, then act. Rapid-fire perfect clicks are themselves a bot signal.
2. Look first. Every browser action attaches the current screenshot — actually
   READ the challenge from the image before choosing an action.
3. One deliberate action per turn; then re-observe (browser_read or the next
   action's screenshot) to confirm the result before continuing.

## PROCESS
1. IDENTIFY the challenge type from the screenshot:
   - a simple checkbox ("I'm not a human"/reCAPTCHA checkbox),
   - an image grid ("select all squares with … / traffic lights / crosswalks"),
   - a slider / drag puzzle ("slide to complete the puzzle"),
   - a text/number CAPTCHA (distorted characters to type),
   - an interstitial that clears on its own (Cloudflare "checking your browser").

2. CHECKBOX: click the checkbox [id] once, then browser_read. Often that alone
   passes. If it then expands into an image grid, continue below.

3. IMAGE GRID: read the instruction text from the screenshot. The grid tiles are
   interactive elements with their own [id]s — identify WHICH tiles satisfy the
   instruction by looking at the image, then click those tiles' [id]s one at a
   time (a short human pause between them; use browser_interact with
   compare=true if you need to confirm a tile toggled selected). When the required
   tiles are selected, click Verify/Next/Skip [id]. If the grid refreshes with new
   images, re-read and repeat. Give it 2-3 rounds before trying a different tack.

4. SLIDER / DRAG PUZZLE: identify the slider handle [id] and the target gap in
   the image. Use action 'drag' from the handle to the target [id], OR
   press_and_hold + observe. Human drag timing is built in. Verify by screenshot.

5. TEXT/NUMBER CAPTCHA: read the characters from the screenshot and 'type' them
   into the input [id], then submit. If ambiguous (0/O, 1/l), pick the most likely
   and be ready to retry once.

6. SELF-CLEARING INTERSTITIAL (Cloudflare/"just a moment"): do NOT hammer it.
   Use wait_for (a few seconds) then browser_read; it usually clears itself once
   the browser passes the passive checks (which this stealth browser is built for).

## IF STUCK
- Do not loop on the same failing selection. After ~3 honest attempts, try:
  reloading the challenge, switching to the audio option if offered (read the
  audio prompt text if a transcript appears), or looking for a "skip"/alternative.
- If the challenge is genuinely unsolvable from the page and no alternative path
  exists, report clearly to the user what challenge is blocking and where, rather
  than spinning.

## VERIFICATION
The challenge is solved when the blocking overlay is gone and the underlying page
(the one you were trying to reach) is visible and interactive in the screenshot.
Confirm from the image, not just from the element list.

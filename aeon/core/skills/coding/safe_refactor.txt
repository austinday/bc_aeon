# CODING SKILL: Safe Refactor Protocol
# Triggered when restructuring existing code (renaming, extracting, moving, reorganizing)
# without changing behavior. Goal: zero behavioral regressions.

1. ESTABLISH A BASELINE:
- Identify how current behavior is verified (tests, a runnable script, expected output). If none exists, create a minimal characterization test that captures current behavior BEFORE refactoring.
- Run it and record the passing baseline.

2. MAP THE BLAST RADIUS:
- List every file that imports, calls, or depends on the code being refactored (upstream and downstream).
- Note interface contracts: function signatures, return types, side effects, file paths, expected flags.

3. REFACTOR IN SMALL STEPS:
- Make ONE structural change at a time (e.g. rename, then re-run baseline; extract, then re-run baseline).
- After each step, re-run the baseline. Never stack multiple unverified changes.
- Prefer write_file for whole-file rewrites under ~400 lines; reserve str_replace for small edits to large files.

4. UPDATE ALL REFERENCES:
- For any rename or move, update every reference found in step 2. Do a bounded, extension-restricted search (e.g. grep -rnI on *.py) to find stragglers.

5. VERIFY:
- Re-run the full baseline. Behavior must be identical.
- If behavior changed, you did not refactor — you introduced a bug. Revert the last step and retry.

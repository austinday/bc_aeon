# CODING SKILL: Safe cross-boundary change propagation
# Use when an implementation or refactor can affect callers, consumers, persisted data, configuration, or runtime behavior beyond one local edit.

## When to use

Use for interface, schema, path, configuration, command, state, or process-boundary
changes and for behavior-preserving refactors with a meaningful blast radius. Skip it
for a truly isolated change whose complete behavior is covered by one local check.

## Preconditions

- State the intended behavior and the contracts that must remain compatible.
- Inspect applicable instructions, current callers and consumers, tests, and
  unrelated dirty-worktree changes that must be preserved.
- Establish a passing baseline. For a behavior-preserving refactor without coverage,
  add or identify a focused characterization check before restructuring.

## Procedure

1. Map the changed surface: symbols, signatures, defaults, serialization, files and
   paths, configuration, side effects, persisted state, and failure behavior.
2. Search current imports, callers, downstream consumers, generated artifacts, and
   operational boundaries that actually depend on that surface.
3. Implement the smallest coherent change. Keep compatibility or migration handling
   explicit, and update references and tests in the same logical change.
4. Validate the changed contract first, then run broader regression checks in
   proportion to impact. Inspect fresh output and the final diff rather than relying
   on an unrelated passing test.
5. Report what was exercised, what changed, and which consumers or environments
   remain unverified.

## Verification

- Behavior-preserving work must still pass its original baseline or characterization.
- Changed behavior must have a focused check proving the new contract and important
  compatibility or failure paths.
- Confirm that no intended reference, migration, or runtime consumer was omitted.

## Stop or adapt

If a correction changes the contract again, remap only the affected propagation path
and rerun its checks. Preserve unexpected unrelated changes rather than overwriting
them. If a consumer cannot be inspected or exercised, state that limitation instead
of repeatedly rerunning the same partial test or claiming complete propagation.

# COMPUTATIONAL BIOLOGY SKILL: Sequence & Bioinformatics Analysis Protocol
# Triggered for tasks involving DNA/RNA/protein sequences, alignments, BLAST-style
# search, FASTA/FASTQ/GenBank handling, or general bioinformatics pipelines.
# Goal: reproducible, correctly-versioned analysis with explicit controls.

1. ENVIRONMENT & PROVENANCE:
- Define the environment in a Dockerfile (Biopython, pysam, samtools, BLAST+, etc. as needed). Do not install on the host.
- Record EXACT versions of every tool and reference database/genome build. Results are meaningless without provenance. Memorize the reference build (e.g. GRCh38 vs GRCh37) — they are NOT interchangeable.

2. INSPECT BEFORE COMPUTING:
- Never blindly cat large sequence files. Use the file analyzer / head a small sample to confirm format, record count, and encoding.
- Validate input integrity: check for truncated records, mixed alphabets, or unexpected headers.

3. PIPELINE AS NUMBERED, IDEMPOTENT SCRIPTS:
- Implement as 0_*.sh / 1_*.sh etc. calling .py in Docker. Each step idempotent (skip already-completed downloads/outputs).
- Use progress bars and print record counts at each stage so silent data loss is visible.

4. CONTROLS & SANITY CHECKS:
- State your positive and negative controls explicitly. A pipeline that runs is not a pipeline that is correct.
- Sanity-check biology: sequence lengths, GC content, ORF presence, alignment identity ranges — confirm they fall in plausible ranges.

5. SAFE SEARCHING ON DATA DIRS:
- Never run unbounded recursive grep/find over raw sequence/binary data — it can freeze the system. Restrict to script extensions or use grep -rnI.

6. VALIDATE OUTPUTS:
- Verify completion by checking actual outputs against expectations, not by the script merely exiting 0.
- Report counts, ranges, and a small sample of results. Save a README describing the pipeline and provenance.

7. TOOLING GOTCHAS — CORRECT CURRENT USAGE:
- BLAST+: build the DB with `makeblastdb -dbtype nucl|prot`; query with `-outfmt 6` (tabular) for parseable output, plus `-evalue` and `-num_threads`. IMPORTANT: `-max_target_seqs 1` does NOT reliably return the single best hit — it is an early-stopping cutoff applied before final sorting, so it can return a non-best hit. To get the top hit, retrieve several and sort by bitscore yourself.
- Use the RIGHT program/matrix for the alphabet: blastp (+BLOSUM62) for protein, blastn for nucleotide, blastx/tblastn when translating. Mixing alphabets or the wrong reading frame is a common silent error — verify the alphabet and frame before trusting hits.
- Biopython: iterate with `Bio.SeqIO.parse(handle, "fasta"|"fastq"|"genbank")` rather than loading all records into RAM. Use `Bio.Align.PairwiseAligner` (the current API); `Bio.pairwise2` is DEPRECATED. `Bio.Entrez` requires `Entrez.email = "..."` and courteous rate-limiting (≤3 req/s without an API key).
- FASTQ quality is Phred+33 (Sanger/Illumina 1.8+) essentially everywhere now; only ancient data is Phred+64 — assume +33 unless a QC tool says otherwise.

# MACHINE LEARNING SKILL: Rigorous ML Experiment Protocol
# Triggered for training/evaluating any ML model or running an ML experiment.
# Goal: trustworthy results with NO leakage, fair baselines, and reported variance.

1. SPLIT BEFORE YOU LOOK:
- Create train/validation/test splits FIRST and hold the test set untouched until the final evaluation. Touching it earlier invalidates the result.
- For grouped/temporal/subject data, split by group/time to prevent leakage across the boundary. Random splits leak in these settings.

2. GUARD AGAINST LEAKAGE (the #1 cause of fake results):
- Fit all preprocessing (scalers, encoders, imputers, feature selection) on TRAIN ONLY, then apply to val/test. Never fit on the full dataset.
- Check no target-derived or future-derived features leak into inputs. Confirm no duplicate rows span train and test.

3. ESTABLISH A BASELINE:
- Always include a simple baseline (majority class, mean predictor, or a trivial model). A complex model is only meaningful relative to it.

4. TRAIN WITH DISCIPLINE:
- Fix and record random seeds. Log hyperparameters, data version, and code state.
- Use the validation set (or cross-validation) for model selection and tuning — NEVER the test set.
- Containerize; maximize available GPU/CPU; checkpoint long runs.

5. EVALUATE HONESTLY:
- Choose metrics appropriate to the task and class balance (accuracy is misleading under imbalance; report precision/recall/AUC/F1 as appropriate).
- Report variance across seeds/folds, not a single cherry-picked number. A result without variance is not yet a result.
- Evaluate on the held-out test set EXACTLY ONCE, at the end.

6. VALIDATE & DOCUMENT:
- Sanity-check for too-good-to-be-true scores (a classic leakage signature) and investigate before celebrating.
- Save a README with data version, splits, seeds, hyperparameters, baseline, and final metrics with variance.

7. TOOLING GOTCHAS — CORRECT CURRENT USAGE (avoid the silent-mistake traps):
- Prevent leakage MECHANICALLY with a sklearn `Pipeline`: put scalers/encoders/imputers/feature-selection INSIDE the Pipeline and pass the Pipeline to `cross_val_score`/`GridSearchCV`, so every preprocessing step is refit on each training fold only. Fitting a `StandardScaler` (or `SelectKBest`, or a target encoder) on all of X before splitting is the single most-common leakage bug and inflates scores.
- Splits: `train_test_split(X, y, stratify=y, random_state=42)` for classification (stratify preserves class balance; omitting it skews small/imbalanced sets). Use `StratifiedKFold` for CV, `GroupKFold` when rows share a subject/group, `TimeSeriesSplit` for temporal data — a plain random `KFold` LEAKS in grouped/temporal settings.
- Metrics: `roc_auc_score`, `average_precision_score`, and log-loss need PROBABILITIES (`model.predict_proba(X)[:, 1]`), not predicted labels — passing labels silently computes a wrong (deceptively low) AUC. For multiclass set `average="macro"`/`"weighted"` explicitly; bare `accuracy` is misleading under class imbalance.
- Early-stopping APIs moved: XGBoost ≥2.0 takes `early_stopping_rounds` in the CONSTRUCTOR (or an `xgb.callback.EarlyStopping` callback), not in `.fit(...)`. LightGBM uses `callbacks=[lgb.early_stopping(50), lgb.log_evaluation(0)]`; its old `.fit(early_stopping_rounds=...)` kwarg is removed. Both need an eval set passed to `.fit`.
- Reproducibility: set `random_state`/`seed` on the SPLITTER, the MODEL, and any sampler/augmenter — one unseeded component makes runs non-reproducible. Report mean ± std across seeds or folds, never a single number.
